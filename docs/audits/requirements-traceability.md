## Non-functional requirements

| ID | Requirement | Status | Evidence / affected files and components | Executed test and result | Risk | AWS impact | Recommended action |
|---|---|---:|---|---|---|---|---|
| NFR-01 | serverless-first | FAIL | Current design is a long-running FastAPI process with synchronous SQLite and long scraping/subprocess jobs. | Architecture/runtime review; 67.57 s map call and long batch workflows observed. | Direct Lambda lift-and-shift would time out or serialize work poorly. | Use managed services, but ECS/Fargate for API/workers rather than forcing Lambda. | Adopt hybrid managed architecture and document serverless exceptions. |
| NFR-02 | AWS und CI/CD | FAIL | No AWS IaC or deployment workflow; CI lacks security, Docker, migration, deploy and rollback gates. | `.github/workflows/ci.yml` inspected; local test/build commands passed. | Manual, unreproducible and unsafe delivery. | Fundamental blocker. | Implement Terraform/CDK, environments, OIDC deployment, staged migration and rollback. |
| NFR-03 | Open-Source-Präferenz | PARTIAL | Core stack is OSS; optional Gemini/Anthropic services are proprietary. No SBOM/licence inventory exists. | Dependency and licence-file inventory. | Licence obligations and vendor dependencies are not governed. | Image/SBOM scanning and model-provider choices needed. | Generate SBOM and third-party/source licence register; retain provider abstraction. |
| NFR-04 | Kosteneffizienz | FAIL | No cost model; 9.37 GB image, 8.81 GB build context and repeated full aggregations are expensive. | Docker image history and runtime timings measured. | Slow pulls, storage/egress and overprovisioning. | Direct deployment would create avoidable ECR/ECS/NAT/RDS cost. | Slim image, S3 data, pre-aggregation, load model and AWS budget alarms. |
| NFR-05 | Skalierbarkeit | FAIL | Single SQLite file, synchronous queries inside async handlers and filesystem locks/status. | Parallel calls queued for about 55 s behind map aggregation. | One heavy user stalls all users; one-host state is not horizontally safe. | Requires PostgreSQL, worker separation and caches. | Remove blocking I/O from event loop and introduce scalable persistence/queues. |
| NFR-06 | Datenschutz und Compliance | FAIL | No auth/RBAC, retention, privacy workflow or protected admin plane; logs/public datasets contain contact/address fields. | Security review, log sample and tracked-secret scan. | Unauthorized mutation and personal-data exposure. | Public deployment prohibited until controls exist. | Complete DPIA/legal review, OIDC/RBAC, redaction, encryption and retention workflows. |
| NFR-07 | Ladezeit der primären Ansichten | FAIL | Cold primary dashboard calls took roughly 28–35 s; map with connections took 67.57 s. | HTTP timing, concurrency test and 45 s headless-browser screenshot. | Far above a practical 3 s target. | Must be solved before capacity planning and public staging exit. | Precompute, cache, paginate and enforce p95 budgets in CI/staging. |
| NFR-08 | Rate-Limiting und polite crawling | PARTIAL | Source clients include retry, sleep/backoff and user-agent tests. API has no inbound rate limit; source terms/robots evidence is incomplete. | Scraper tests passed; middleware/config inventory found no API limiter. | Source blocking and public abuse remain possible. | Need WAF/API throttles and centrally enforced source quotas. | Add per-source policy configuration, robots/terms review and inbound throttling. |
